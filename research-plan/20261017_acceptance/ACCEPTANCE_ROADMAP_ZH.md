# GWAS：面向可支持接收的补强方案
日期：2026-10-17
状态：研究与实验设计，尚未执行以下新增实验；不构成录用保证。
依据：[独立审稿](../../review-stage/independent_review_20261017/REVIEW_ZH.md)与当前 S61–S66 代码、归档结果。

## 结论与论文主线

建议以主动分支为主，优先按安全会议的实证研究组织；NeurIPS／ICML／ICLR 作为需要进一步一般化贡献的路线。两种定位都允许负面结果，不应预先把“必须赢”“必须显著”当作验收标准。

主问题固定为：

> 在合作方只能作有限、保持逐 SNP 基因型计数的输入修改，只能看到少数有限精度的最终 PCA 输出时，能否获得强被动攻击之外、可以在独立数据上复制的成员信息？哪些精度、谱结构和输出策略会使这种能力出现或消失？

现有被动 PC/AF 排序作为背景与基线，manifest 作为工程原型或附录，不能共同充当三个相互替代的主要创新。无需删除旧代码或结果。若保留防护系统贡献，必须重新验证真实权限边界；修补 audit hook 的一个事件不能使它变成可靠沙箱。

“消除拒稿理由”与“增加新贡献”是两个阶段。先修对照、权限和评价，确认现有现象仍成立；再研究有限精度下的可恢复能力。只完成纠错，不能自动把已知 PCA 泄漏变成顶会新发现。

## G0：先冻结实验合同，避免继续在旧数据上选择结论

交付一份配置文件，逐项写明：

- 攻击方、诚实方和输出接收者；攻击方能选择初始输入，还是能在同一诚实队列上多次修改后重跑。
- 逐个可见对象：feature loadings V、相应 eigenvalues Lambda、AF/mean/scale、位点保留掩码、本地 scores。不能把本地 scores 当成 feature loadings，也不能把允许解密 V 推成同时可得 Lambda。
- 位点选择、LD pruning、单态位点、缺失值填补、中心与尺度、打分截断、浮点格式和打印精度。
- 输出预算 q、修改行数与基因型数量、候选搜索计算量、已知成员及已知非成员的数量和来源。
- 方向、阈值、秩阈值、融合权重、正则化强度如何由影子/校准数据确定；最终测试标签只用于评估。
- 主指标、最小有用效应、区间与失败条件。最小收益按实际用途事先定义，不能在看到最终数据后选。

现有 1000G 和已经反复查看的染色体结果作为开发材料。外部来源先完成可用性、重复个人与亲缘检查，再冻结最终测试划分。不能把旧数据重新随机切一次称为新的最终验证。

预处理至少区分两种信息合同：
P0：只给外部参考参数，不提供诚实队列统计；
P1：给实际接口明确发布的联合 AF/中心/尺度。
P1 的“不增加谱输出”对照已有诚实队列信息，必须直接利用这些信息；它不必等于随机水平。P0 是否能在所选软件正确实现，应核对实际算法，不能擅自当作 PLINK 默认行为。

## G1：优先做能决定是否继续的公平复算

先用原有 chr22 三个 cohort、既有五次划分做诊断，优先重读现存真实输出；若原始导出文件缺失，再重导出。无需先下载大队列或重跑整套 GWAS。

### 必须同信息、同预算的比较

| 比较臂 | 作用 |
|---|---|
| 候选基因型本身，不给诚实队列统计 | 排查批次、祖源或候选选择就能分类的情况 |
| 公开预处理参数，不增加谱输出 | 包含直接 AF/尺度攻击、随机子空间、已知成员 PCA |
| 条件化 AF | 用相同已知成员合法扣除贡献 |
| 条件化单次谱输出 | 用相同已知贡献扣除；只使用实际可见输出 |
| 条件化 AF＋单次谱＋候选统计的联合攻击 | 补上 max(AF,单谱) 不能代表的融合基线 |
| 相同 q 次、输入不变 | 排除重复输出、近似求解器随机性或简单去噪解释 |
| 同修改与输出预算的随机交换 | 主动机制的基本证据 |
| 新自适应策略 | 仅在前面的机制成立后检验算法增量 |

主动分支也应比较扣除同一批已知成员贡献与不扣除，避免把可用信息只给某一方。所谓“强基线”应写成所实施、独立验证过的基线，不能称为所有可能攻击的最优上界。

两套打分预处理分别复查：所有比较臂都不截断；所有比较臂都按相同方式截断。这里的“打分截断”不必改变原来的 PCA 输入。若要改变 PCA 输入的标准化/截断，则必须重新定义和计算该谱问题，不能继续把旧输出当作新变换下的特征对。

先在已有大辅助知识设定修复复算，再加入 0% 目标诚实成员已知的设定；后者的定向、参数和融合训练全部来自独立影子实验。完整敏感性再用 0%、5%、10%、50%（同时报告实际人数）。50% 可以保留为有明确来源的强辅助知识场景，不能作为默认现实条件。

### 主指标与继续条件

诊断阶段报告配对 AUROC、固定校准阈值后的 TPR、实测 FPR、TP/FP 人数，以及逐划分结果。不能在最终测试 ROC 上挑阈值，再称为已校准工作点。

最初使用数据支持的 FPR 范围；几十个非成员不适合稳定验证 1% FPR。需要更低误报率时，先安排足够的祖源匹配、独立非成员样本；不能靠混入另一队列或祖源增加样本量。

继续主路线的条件是：实际输出精度下，随机主动臂相对联合强被动基线仍有可解释、有实际意义的增量，且不完全由公开预处理或候选本身解释。已有五次划分只用于诊断，不作为最终确认。

若统一后增量消失，记录反证并研究失效边界；不要通过改种子、换祖源或筛 SNP 找回显著性。若只剩某个极小场景，就缩小问题，不能继续使用普遍风险叙事。

## G2：落实一个真实接口或明确配置的端到端场景

目前可以确认 PLINK 提供 allele weights、频率导出和投影流程；尚未确认某个实际协作部署同时满足全部主动权限。

[PLINK 官方文档](https://www.cog-genomics.org/plink/2.0/strat)明确支持 allele-wts；[PCA 投影流程](https://www.cog-genomics.org/plink/2.0/score#pca_project)给出参考载荷和 AF 的导出与复用。它们证明对象可导出，不证明合作方拥有反复改输入并重跑的工作流权限。

[SF-PCA Step 8](https://pmc.ncbi.nlm.nih.gov/articles/PMC11044025/)允许按应用要求选择解密 PCs 或投影数据，也允许持续加密；不自动证明 Lambda、精确预处理参数也向攻击者发布。[SF-GWAS 官方代码](https://github.com/hhcho/sfgwas)不能直接作为默认明文载荷输出的依据。

最低端到端交付：

1. 锁定软件版本、配置、角色及每次重跑的授权条件。
2. 诚实数据放在独立进程或服务内；攻击程序不能读取其文件、缓存或评估矩阵。
3. 攻击程序只消费实际交付的输出；把所有查询包括搜索期间试探的查询计入预算。
4. 留存每轮输入修改数量、固定诚实队列的校验、可见输出字段、序列化精度和日志。
5. 对相同配置复现单次基线、输入不变的 q 次输出、随机主动输出和任何新方法。
6. 若依赖自建的明文导出选项，明确标为研究配置；不能称为发现原系统默认漏洞。

若系统只给本地投影 scores，就要重新研究该输出下的识别问题；不得临时给攻击者追加 V 和 Lambda 使恒等式成立。若没有任何可信的重跑场景，应将论文定位为明确接口下的条件性风险，并相应收缩实际部署主张。

## G3：把精度失败转成可解释的研究贡献

当前固定相对 1e-9 截断，与文本量化和求解器误差没有对应关系。新方向应研究“有多少方向在误差之上仍可用”，而不仅是精确数学秩。

### 先做稳健估计，再决定是否值得做新自适应策略

第一步，从实际格式和算法得到输出误差来源：V/Lambda 的文本量化、近似 PCA 残差、公开参数的舍入、缺失处理。最坏误差上界与影子数据估计的经验噪声分别报告，不能互相代替。

在堆叠输出上写：
tildeY = C_H tildeQ + E。
这里 E 代表相对于实际诚实散度算子的测量残差。真实 C_H 只可由评估程序用于检查误差；攻击方必须依赖公开界、求解器信息或影子估计。

比较原 1e-9 截断、精度匹配的截断 SVD，以及正则化估计。参数只在影子数据上选择。对成员推断主要检查 Y 的稳定子空间；对算子或目标统计恢复，单独研究 Q 的求逆误差。二者不能互作成功证明。

对于一个预先确定的候选方向 x，可求解低维系数 a，让 tildeQ a 接近 x，并约束 ||a||，再估计：
x^T C_H x ≈ x^T tildeY a。

由直接代数可得：
|x^T C_H x - x^T tildeY a|
≤ ||x|| (||C_H||_op ||x-tildeQ a|| + ||E||_op ||a||)。

该式解释“覆盖误差”和“噪声放大”的权衡，是设计入口，不能单独称为新理论。新贡献应来自基因型约束下可达的权衡、可信的误差估计，以及对未参与拟合条件的成功/失败预测。

第二步才研究输入选择：当前目标对齐×几何新颖性可以偏好远小于输出误差的新方向。可以尝试以“预计新增的稳定方向”或“预计降低的目标统计误差”为目标，使用影子面板、已知合作方贡献和过去可见输出做预测。该方法尚未验证，不预设它能超过随机交换。

安全实证论文不必强求自适应超过随机：如果随机合法修改已经造成有实际意义的额外信息，这本身值得报告。若坚持算法贡献，就必须在同输出、修改和合理计算预算下稳定胜过随机，并披露失败条件。

### 理论应证明什么

保计数块交换给出具体结构：设两行标准化向量的差为 u+v，u 支持在块外、v 支持在块内，交换后差为 u-v。在未归一化散度尺度，
DeltaK = -(u v^T + v u^T)，rank(DeltaK)≤2；
因 u 与 v 正交，||DeltaK||_op=||u||||v||。
若散度带 1/M 等归一化，界必须乘同一系数。

由此研究输入预算、谱间隙和方向旋转的关系，再纳入输出误差，说明什么时候新增方向不可分辨。谱扰动上界不是攻击收益下界，不能保证每次交换都产生有用方向。

纯粹的线性测量 Y=CQ 只确定 C 在 Q 张成空间上的作用；完整恢复还需足够覆盖或额外可验证的低秩/PSD 等结构。qk 小于特征数不自动排除有结构恢复，也不能支持一般完整恢复。若使用结构约束，它们必须被陈述并实验检验。

## G4：优先加入近似 PCA 和独立受试者验证

[PLINK 官方文档](https://www.cog-genomics.org/plink/2.0/strat)说明 approx 使用随机近似算法。精确特征方程的入口在真实近似输出下应改为带残差的关系。必须比较：

- 精确求解与 approx；
- 输入不变但求解器随机种子变化，与输入真正变化；
- 真实文本导出、float32，以及更粗精度边界；
- 输出 1/2/4/8 次；q=16 作为额外边界，不能只挑最好点；
- k、修改预算和已知成员比例的分层敏感性。

先做小规模正交筛查，找到影响因素后冻结关键设置；不要一次铺满笛卡尔积。输出精度和近似计算是主工作点，float64 只作上界。

公开外部验证候选是 HGDP：[IGSR 官方入口](https://www.internationalgenome.org/data-portal/data-collection/HGDP/)、[CEPH 数据入口](https://cephb.fr/en/hgdp_database.php)。下载前先核对样本、位点、访问条件和可支持角色规模。本计划没有下载或验证该数据。

按样本映射和基因型检查排除跨来源重复个人及近亲。每个最终评估中，诚实成员、非成员、参考和校准尽量来自同一数据来源，并匹配祖源；不能用 1000G 成员对 HGDP 非成员作为主实验，否则可能主要测到来源差异。1000G 高覆盖版本不能自动叫独立队列；新增相关人员也不能自动作独立个人。

真实样本阶梯以实际容量为准。更大的 n/M 可以用机制清晰的模拟或半合成扩展，但必须分开标注，不称为真实大队列。n、M、k 和群体组成应有固定其他因素的比较。

实现上应避免扩大位点数就构造 M×M 私有散度矩阵。攻击中的 K V 可以写为 Z_P^T(Z_P V)；评估的 C_H x 可以写为 Z_H^T(Z_H x)。保存窄矩阵 Q/Y 并用紧凑 SVD，完整矩阵恢复只在可负担的专门实验中进行。这是规模可行性的工程改进，本身不作为科学创新。

## G5：补一张隐私—科学效用图

防护至少包括：固定外部参考 basis、只向各方交付必要 scores/保持计算密文、谱输出舍入，以及有完整机制定义的 DP-PCA 对照。若讨论 DP，必须把 AF、中心、尺度、位点筛选和多次发布一并纳入机制及计账；不能给 eigenvalues 加噪声后称整个管线满足 DP。

在重复的零效应和有因果效应模拟表型上，报告假阳性、功效、效应偏差、PCA/投影误差、个体 QC 失败率和运行/通信代价。λGC 和最小 p 值作为辅助指标。模拟数由预定 Monte Carlo 精度与计算预算决定，先小规模确认实现，再扩大，不为使曲线好看重复改配置。

主要问题是：在相当的分析效用下，哪些发布策略减少了攻击的操作性收益，代价是什么？“不发布载荷”是否可用，要结合各站点真正需要完成的投影和分析任务评估。四位小数下某攻击失效，不是安全证明。

## 主文应交付的六张图

| 图 | 要回答的问题 | 能改变审稿判断的证据 |
|---|---|---|
| 1：公平强基线与 q | 主动修改到底新增什么 | 同预处理、同信息、实际精度下超过联合被动比较；逐条件失败也完整展示 |
| 2：真实接口过程 | 这些权限与输出确实存在吗 | 版本、配置、角色隔离、输出字段与完整查询计数 |
| 3：精度×近似误差 | 数值方向何时变成可用信息 | 稳定秩/误差模型预测未拟合条件，而非只拟合已有曲线 |
| 4：独立受试者验证 | 是否超出同一个面板 | 事先冻结方案、样本去重、匹配角色、固定阈值后的 TP/FP 与区间 |
| 5：n/M/k/已知比例 | 能力边界在哪里 | 单因素可解释变化，明确模拟与实测容量 |
| 6：隐私—效用 | 防护是否保留必要分析能力 | 同效用的风险、校准、功效及成本比较 |

正文只保留能支撑中心主张的图和论证。旧的自引用负例偏差、被动排序、其他诊断控制和治理实现可进入背景、补充材料或单独工程报告。

## 两条会场路线的区别

安全顶会：重点是可信输出合同、受约束攻击、同信息基线、现实精度与独立复制。一个有清楚必要条件、失败边界和效用代价的随机攻击，也可能比缺乏部署证据的复杂算法更有说服力。

ML 顶会：需要进一步提出可推广的受约束主动谱识别问题，并通过新方法、非平凡可辨识性结论，或足够有解释力且能预测外部条件的实证规律推进认识。不强制“必须有定理”，也不认为添加定理或第二领域数据就自动满足创新。GWAS 应成为检验该一般问题的严格实例。

若端到端权限无法落实，但稳定识别问题有新的普遍结果，可保留 ML 路线；若新方法不优于随机，但现实风险扎实，可集中安全实证路线；若公平处理与现实精度下增量均消失，应转向失效边界，而不是维持已有成功叙事。

## 投稿前内部验收

以下都应有具体文件与结果：
公平基线通过；发布合同逐项有证据；攻击不读取私有评估矩阵；实际输出与求解器设定下存在预先定义的有用增量；独立复制或明确受限范围；科学效用与防护代价；论文主张、摘要和图表与最终结果一致；独立复查能从配置复现核心图。

这些条件用于判断“主要拒稿理由是否已解决”，不等于会议官方门槛，也不保证接收。本轮仅交付方案，没有将任何新增实验、算法或数据访问标记为完成。
